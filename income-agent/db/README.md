# הדאטהבייס

**פרויקט Supabase: `income-scout`** · ref `fkerxtxltquruhsnwgpz` · אזור eu-central-1

זהו **מקור האמת** של המערכת. קבצי ה-Markdown ב-`../reports/` הם עותק לקריאה נוחה,
ו-`../memory/` הוא גיבוי — אבל הסוכן קורא וכותב לדאטהבייס.

הסכימה המלאה: [`schema.sql`](schema.sql).

## הטבלאות

| טבלה | מה יש בה |
|---|---|
| `runs` | ריצה יומית אחת + מספרי המשפך, ודגל `degraded` לריצה שרצה בתנאים חסרים |
| `ideas` | כל רעיון שנבחן אי פעם, כולל שנפסלו. עם הציון, המספרים, והתוכנית המלאה |
| `evidence` | הראיות לכל רעיון — לינק, ציטוט, `tier`, `source_name` ו-`is_buyer_voice` |
| `feedback` | **התגובות שלך.** המקור בעל המשקל הגבוה ביותר בכל ריצה |
| `directives` | הנחיות קבועות שלך. גוברות על כל כלל אחר |
| `lessons` | לקחים ארוכי טווח שמשנים חיפושים עתידיים |

## התצוגות שכדאי שתכיר

```sql
select * from v_pending_decisions;    -- מה ממתין להחלטה שלך, לפי ציון
select * from v_funnel;               -- כמה מועמדים באמת נסרקו בכל ריצה
select * from v_rejection_patterns;   -- מה נדחה ולמה — הדפוסים שמכווננים את הסוכן
select * from v_evidence_quality;     -- האם הציונים נשענים על ראיות אמיתיות
```

`v_funnel` היא הבדיקה החשובה: אם `raw_candidates` יורד מתחת ל-32,
הסוכן לא סורק מספיק רחב וצריך לכוונן.

**`v_evidence_quality` היא בקרת האמינות.** היא סופרת לכל רעיון כמה מקורות
**מאומתים ועצמאיים** באמת יש לו, והאם יש בהם קול קונה — ומחשבת את התקרה
שחלה על רכיב "עוצמת הצורך" לפי `../criteria/scoring.md`.
בריצה הראשונה היא תפסה מיד רעיון שקיבל 68 על סמך ארבע ראיות
שכולן ממפרסם יחיד, והורידה אותו ל-66. אם רעיון מציג ציון גבוה
ו-`need_score_cap` שאינו "ללא תקרה" — הציון מנופח.

## איך לתת משוב

זה מה שמכוון את המערכת. שתי דרכים:

**דרך הסוכן** — פשוט תגיד לי בצ'אט: "רעיון X מעניין, Y דחוי כי הוא דורש מכירה טלפונית",
ואני אכתוב לטבלאות.

**ישירות ב-SQL:**

```sql
-- משוב על רעיון ספציפי. ה"למה" שווה יותר מהפסק דין
insert into feedback (idea_id, verdict, note)
values ('<idea-uuid>', 'rejected', 'דורש מכירה טלפונית, לא מתאים לי');

-- הנחיה קבועה שתקפה לכל הריצות הבאות
insert into directives (directive)
values ('אל תציע יותר רעיונות שדורשים מכירה טלפונית');

-- לכבות הנחיה
update directives set active = false where id = '<uuid>';
```

## אבטחה

RLS מופעל על כל הטבלאות **ללא policies** — כלומר `anon key` לא רואה כלום.
הגישה היחידה היא service role / Supabase MCP.
אם תרצה בעתיד דאשבורד שקורא מכאן — צריך להוסיף policies במפורש, לא לכבות RLS.
